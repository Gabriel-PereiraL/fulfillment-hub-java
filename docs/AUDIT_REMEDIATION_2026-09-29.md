# Audit remediation — 2026-09-29

This is the evidence ledger for the F01–F15 remediation. A finding is marked fixed only after a reproducing test and the relevant regression checks pass.

| Finding | Current status | Confirmed evidence | Remediation evidence |
|---|---|---|---|
| F01 — authorization before side effects | Fixed | `OrderService.cancel` called the delivery provider after checking only order state and before resource ownership. | Provider access was removed from the HTTP command. Cancellation now commits the authorized local transition and durable `OrderCancelled` event before provider work. `customerCannotCancelAnotherCustomersOrderOrScheduleProviderEffects` proves a different customer cannot change the order, restore stock, or schedule the only message that can reach providers. Runtime regression: 44 domain + 3 resilience + 10 integration tests passed. |
| F02 — resumable payment | Fixed | A lost create response left no provider ID; reconciliation queried only rows that already had one. | Creation now persists `Submitting`, records transport/5xx uncertainty as `Unknown`, closes the attempt, and reconciliation resumes payments without provider ID using the original idempotency key. `paymentRecoversWhenProviderExecutesButEveryResponseIsLost` proves the remote effect occurs once and the original provider payment is adopted after recovery. Targeted build: 44 domain + 3 resilience + 1 integration test passed on 2026-09-30. |
| F03 — resumable delivery | Fixed | An existing local delivery discarded its persisted quote and then dereferenced a missing quote; duplicate provider responses were not adopted. | Retrying now locks and reuses the active delivery, reloads its persisted quote, renews only an expired quote, preserves the idempotency key, and accepts the provider's 409 body as the existing resource. `deliveryRecoversPersistedQuoteAndAdoptsDuplicateAfterLostResponse` proves one local delivery/quote and one key after a lost response. Targeted build: 44 domain + 3 resilience + 1 integration test passed on 2026-09-30. |
| F04 — domain governs runtime | Fixed | Provider snapshots directly replaced payment and delivery row state, allowing stale-state regression. | `ProviderStatePolicy` is now the shared transition/temporal policy used by payment and delivery provider paths. Five policy tests cover stale, terminal and forward transitions. The payment integration test applies Paid and then a newer Pending snapshot and proves the persisted status remains Paid. |
| F05 — durable HTTP idempotency | Fixed | Order commit and idempotency completion used independent transactions, leaving an unrecoverable `InProgress` crash window. | Migration V5 links the reservation to `order_id`. Order, stock, outbox and that association commit together; an incomplete response can be reconstructed and completed on replay, while `release` cannot delete a committed association. `committedOrderIsRecoveredWhenIdempotencyCompletionNeverRan` proves one order and one stock reservation across the crash window. |
| F06 — consumer claim/dedup | Fixed | The business effect ran before the processed-message insert; concurrent workers could both execute it. | Migration V6 turns processed messages into durable claims. SQS now acquires a per-event owner/lease before work, retries abandoned claims, and completes/releases only with the current owner token. Remote exactly-once is not claimed; provider effects remain protected by durable workflows and stable keys. |
| F07 — webhook claim | Fixed | `Processing` had no owner token or lease and completion did not validate ownership. | Inbox processing now atomically claims with owner/lease, recovers expired Processing, persists retry schedule, conditionally finishes by owner and makes SQS ack depend on completion. `twoWorkersCannotClaimTheSameWebhookAndExpiredLeaseIsRecoverable` proves one concurrent claim and recovery after expiry. |
| F08 — reconciliation | Fixed | Jobs had no duplicate guard and swallowed runtime failures. | Delivery reconciliation now locks the row and no-ops an already persisted provider snapshot; failures are emitted as structured warnings instead of disappearing. Provider workflows remain idempotent under duplicate job selection. |
| F09 — permanent failures | Fixed | Permanent provider rejection was repeatedly selected by reconciliation. | Delivery 4xx responses other than 408/429 now become `FailedPermanent`, cancel the order and emit the durable cancellation/refund compensation; the failed delivery is no longer eligible for recreation. |
| F10 — missing event handlers | Fixed | Known event types without a handler were silently marked processed. | Every required outbox event now requires an installed handler; absence enters retry/failure rather than Processed. The former acceptance test was replaced with the required-failure assertion. |
| F11 — observability | Partially fixed | Reconciliation failures were swallowed and workflow/backlog evidence was incomplete. | Reconciliation failures now produce structured logs; correlation IDs, Prometheus, provider retry/circuit metrics, OTLP export and worker health are present. Complete outbox-to-consumer trace restoration and workflow/backlog age gauges remain not verified, so the full finding is not claimed fixed. |
| F12 — Kubernetes operations | Fixed; restart scenario not verified | Local PostgreSQL lacked persistence and the worker lacked health signaling. | Local PostgreSQL now uses a PVC. The worker writes a progress heartbeat to writable `/tmp`, has readiness/liveness probes, resources/security context and a 60-second termination grace period. |
| F13 — fixed credentials in Sistema-portaria | Fixed in HEAD; rotation/history decision remains | The audit observed database credentials in `db.py` and fixed login credentials in `logic.py`; their real-world validity was not verified. | Commit `5694124` in Sistema-portaria removes fixed credentials from HEAD, requires environment-backed DB configuration and PBKDF2 password hashes, and adds a safe env example. Potentially real historical credentials must be rotated; history was not rewritten. |
| F14 — supply chain | Fixed; remote CI and final image scan pending | CI used mutable action tags, scanned only API, lacked wrapper and omitted E2E. | Added Maven Wrapper 3.9.16, pinned every Action to a commit, narrowed permissions, added job timeouts, E2E and a three-image Trivy matrix. Tomcat/Jackson High/Critical upgrades and gates remain. |
| F15 — leases/visibility | Fixed within declared 300-second work budget | Outbox lease completion had no ownership token; SQS visibility had no renewal for long work. | Outbox claims carry owner/fencing, renew before dispatch and limit batches. Domain/webhook consumers receive one message at a time and extend visibility to 300 seconds before work; provider timeout/retry budgets fit inside it. |
